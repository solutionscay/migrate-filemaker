## Conventions

- Resource names are plural and kebab-case: `/api/v1/invoice-lines`
- IDs in URL path: `/api/v1/invoices/:id`
- Nested resources for strong parent-child: `/api/v1/invoices/:id/lines`
- Query parameters for filtering: `?status=active&sort=created_at&order=desc`
- Standard HTTP methods: GET (read), POST (create), PUT/PATCH (update), DELETE (remove)
- Standard response codes: 200 (OK), 201 (Created), 204 (No Content), 400 (Bad Request), 401 (Unauthorized), 403 (Forbidden), 404 (Not Found), 422 (Validation Error)

## Authentication Endpoints

| Method | Endpoint | Description | Auth |
|---|---|---|---|
| POST | `/api/v1/auth/login` | Login with credentials | None |
| POST | `/api/v1/auth/logout` | End session | Required |
| GET | `/api/v1/auth/me` | Get current user profile | Required |
| PUT | `/api/v1/auth/password` | Change password | Required |

## Error Response Format

All error responses follow this structure:

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Human-readable error message",
    "details": [
      {
        "field": "email",
        "message": "Must be a valid email address"
      }
    ]
  }
}
```

## Pagination Response Format

List endpoints return paginated responses:

```json
{
  "data": [ /* array of resources */ ],
  "pagination": {
    "page": 1,
    "limit": 20,
    "total": 150,
    "pages": 8
  }
}
```
